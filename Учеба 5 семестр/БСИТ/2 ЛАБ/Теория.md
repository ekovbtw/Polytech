# Основные термины
**Сервис** (служба) - системный процесс, предоставляющий функциональность, не связанную с интерактивным пользователем (работает фоном).
Основные признаки службы: 
1. работает фоном, без окон
2. может запускаться до входа в систему
3. видна в специальном списке services.msc - "Службы" 

**SCM** (Service Control Manager) - системный процесс *Service.exe*, который создает, запускает, останавливает и удаляет службы. Наша служба должна уметь регистрироваться в *SCM*, докладывать ему текущее состояние, ожидать команду STOP. 
**SCP** (Service Control Program) - программа управления сервисом. В ней используются SCM API функции: CreateService, DeleteService, StartService. 

## Процесс запуска
Когда вводим команду `myservice.exe install` происходит следующее: 
1. запускается обычный процесс, с правами от учетной записи
2. в SCP части запускается SCM API 
3. инициализируется служба в реестре (HKLM\SYSTEM\CurrentControlSet\Services)
4. записывается путь к myservice.exe

Когда приходит команда `start`:
1. SCM запускает новый экземпляр myservice.exe

### Проблема
Проблема состоит в том, что процесс не знает ради чего его вызвали: ради *install* регистрации или *start* ради сервиса. 

Как он различает: 
```
if (argc - 1 == 0) {
    // ... StartServiceCtrlDispatcher ...
} else if (wcscmp(argv[argc-1], _T("install")) == 0) {
    InstallService();
}
```

Когда запускает SCM, то аргументов при запуске - нет. Если запускаем мы, то указываем аргументы: install, remove и так далее. Поэтому ветка без аргументов - SCM.
