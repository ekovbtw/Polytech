**Сервер** — тот, кто пассивно _слушает_ порт и ждёт входящих подключений (`listen`).
**Клиент** — тот, кто активно _устанавливает_ соединение (`connect`).
Порядок соединения: 
1. Клиент инициализирует соединение, отправляя запрос серверу
2. Сервер постоянно находится в слушающем состоянии, потому что клиент не способен запустить сервер самостоятельно

Необходимо использовать шифрование данных, проверку формата и аналогичные методы обеспечения безопасности, для защиты работоспособности сервера и целостности данных. 

**state** - состояние, которое сервер запоминает, чтобы использовать в будущих запросах от одного и того же клиента. 
**stateless** и **statefull** - свойство архитектуры сервера, проектное решение. **stateless** - свойство, при котором сервер не запоминает состояние клиентов. **statefull** - противоположное свойство, запоминающее состояние клиентов.   

**statefull** например запоминает: 
1. Факт аутентификации: к примеру, клиент ввел данные для аутентификации пару минут назад, следовательно, сервер не запрашивает их повторно. Так работают сессии на сайтах (session-куки). 
2. Прогресс многошаговой операции: например, сохранение корзины в онлайн-магазине
3. Количество блоков данных принятых от клиента (для корректности работы протокола)
4. Накопленные настройки сессии (например, настройка на перевод на русский язык сайтов)

*IP и PORT* - не являются компонентами свойства **statefull**, это базовые данные о клиенте, которые хранятся пока сокет существует. 

В лабораторной работе запросы не зависят друг от друга, следовательно хранить состояние предыдущего запроса от клиента бессмысленно. Значит реализовывать сервер будем опираясь на **stateless** свойство. 

У **stateless** свойства есть свои плюсы: 
1. Легче отлаживать
2. Выше надежность (меньше рассинхронизации)
3. Чем меньше сервер хранит данных, тем меньше злоумышленник может навредить серверу: *resource exhaustion (истощение ресурсов, когда открыто много сессий от одного и того же клиента), подделка чужой сессии или данных, противоречивые запросы, ломающие логику сервера*. 

В Windows для подключения сетевых функций используется библиотека *winsock2.h*, реализация этих функций находится в файле *ws2_32.lib*, поэтому инициализация выглядит так: 

```
#include <WinSock2.h> // библиотека для сетевых функций
#pragma comment(lib, "ws2_32.lib") // сообщение линковщику, о реализации в ws2_32.lib
```

Сама инициализация Winsock (необходима, потому что сеть затрагивает множество компонент,  ресурсов, а следовательно одного объявления заголовка не достаточно) выполняется через функцию `int WSAStartup(WORD wVersionRequested, LPWSADATA lpWSAData);` где:
1. wVersionRequested - версия Winsock. Задается в виде MAKEWORD(number, number). Например: MAKEWORD(2,2) **Макрос `MAKEWORD(a, b)`** на этапе компиляции сам вычисляет и выдаёт готовое значение типа `WORD`
2. lpWSAData - указатель на структуру WSAData, которую Winsock заполнит информацией о реализации Winsock. 
Выключается Winsock функцией `WSACleanup()`. 


Сокет (от англ. гнездо/розетка) - механизм, который позволяет общаться между системами по сети. С точки зрения лабораторной, сокет - дескриптор-число, который привязан к конкретному каналу связи, потому что настоящий сокет находится на уровне kernel space, что не позволяет с ним работать на прямую, только лишь через дескриптор. 

Функция создания сокета выглядит так: 

```
SOCKET WSASocket(
    int af,
    int type,
    int protocol,
    LPWSAPROTOCOL_INFO lpProtocolInfo,
    GROUP g,
    DWORD dwFlags
);
```

1. af (adress family) - семейство адресов, IPv4 или IPv6. Для IPv4 - AF_INET, который нам и потребуется
2. type - тип сокета, SOCK_STREAM - потоковый сокет (TCP), SOCK_DGRAM (UDP) датаграммный сокет
3. protocol - поскольку тип уже все определил (TCP или UDP), тут ставят 0
4. lpProtocolInfo - не нужно, для продвинутых сценариев 
5. g - группа сокетов, используем 0 
6. dwFlags - флаги сокета, создание происходит флагом `WSA_FLAG_OVERLAPPED`, он помечает, что сокет способен к асинхронным операциям. 

Для сетевых функций код ошибки берётся не из возвращаемого значения, а отдельным вызовом — **`WSAGetLastError()`**. Это функция, которая возвращает числовой код последней сетевой ошибки в текущем потоке.

Пример: 

```
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>
#include <WinSock2.h>
#pragma comment(lib, "ws2_32.lib")

int main()
{
	WSAData wsaData;
	int WSAStartupResult = WSAStartup(MAKEWORD(2, 2), &wsaData);
	if (WSAStartupResult != 0)
	{
		printf("WSAStartup failed with error: %d\n", WSAStartupResult);
		return 1;
	}
	printf("WSAStartup succeeded.\n");


	SOCKET listenSocket = WSASocket(AF_INET, SOCK_STREAM, 0, NULL, 0, WSA_FLAG_OVERLAPPED);
	if (listenSocket == INVALID_SOCKET)
	{
		printf("WSASocket failed with error%d\n", WSAGetLastError());
		WSACleanup();
		return 1;
	}
	printf("WSASocket succeeded.\n");


	closesocket(listenSocket);
	WSACleanup();
	return 0; 
}
```

SOCKET - беззнаковый тип, следовательно проверка (listen_socket == INVALID_SOCKET) - верна, поскольку если сравнивать с -1 (как обычно), то будет сравнение с максимально положительным беззнаковым числом (например 255 для unsigned char). 

После создания сокета, необходимо привязать его к адресу и порту сервера, это выполняется командой `bind()`. 
Порт - отдельный номер сетевого адреса, предназначенный для регулирования принятия данных (чтобы конкретный клиент шел к конкретной программе на сервере). 
Чтобы передать bind конфигурацию сервера, нужно заполнить структуру: 

```
struct sockaddr_in {
    short          sin_family;   // семейство адресов
    unsigned short sin_port;     // порт
    struct in_addr sin_addr;     // IP-адрес
    char           sin_zero[8];  // заполнитель, не используется
};
```

1. sin_family - то же самое, что и при создании сокета (IPv4 - AF_INET)
2. sin_port - собственно порт
3. sin_addr - собственно IP-адрес 

Перед заполнением структуру надо **обнулить целиком**. Это делается `memset(&addr, 0, sizeof(addr));`. 

**Little-endian** («остроконечный с хвоста») — младший байт первым.
**Big-endian** («остроконечный с головы») — старший байт первым. Этот порядок исторически принят **в сети** как стандартный, его называют _сетевым порядком байт_ 
- **`htons`** = **h**ost **to** **n**etwork **s**hort — преобразует 16-битное (короткое, 2 байта) число из хостового порядка в сетевой. **Порт** — 16-битный, поэтому `htons(9000)`
- **`htonl`** = **h**ost **to** **n**etwork **l**ong — то же для 32-битного (длинного, 4 байта) числа. **IP-адрес** — 32-битный, поэтому `htonl(INADDR_ANY)`.
- Есть и обратные функции — `ntohs`, `ntohl`
