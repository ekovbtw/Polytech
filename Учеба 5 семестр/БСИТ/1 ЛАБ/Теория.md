**Сервер** — тот, кто пассивно _слушает_ порт и ждёт входящих подключений (`listen`).
**Клиент** — тот, кто активно _устанавливает_ соединение (`connect`).
Порядок соединения: 
1. Клиент инициализирует соединение, отправляя запрос серверу
2. Сервер постоянно находится в слушающем состоянии, потому что клиент не способен запустить сервер самостоятельно

Необходимо использовать шифрование данных, проверку формата и аналогичные методы обеспечения безопасности, для защиты работоспособности сервера и целостности данных. 

**state** - состояние, которое сервер запоминает, чтобы использовать в будущих запросах от одного и того же клиента. 
**stateless** и **statefull** - свойство архитектуры сервера, проектное решение. **stateless** - свойство, при котором сервер не запоминает состояние клиентов. **statefull** - противоположное свойство, запоминающее состояние клиентов.   

**statefull** например запоминает: 
1. Факт аутентификации: к примеру, клиент ввел данные для аутентификации пару минут назад, следовательно, сервер не запрашивает их повторно. Так работают сессии на сайтах (session-куки). 
2. Прогресс многошаговой операции: например, сохранение корзины в онлайн-магазине
3. Количество блоков данных принятых от клиента (для корректности работы протокола)
4. Накопленные настройки сессии (например, настройка на перевод на русский язык сайтов)

*IP и PORT* - не являются компонентами свойства **statefull**, это базовые данные о клиенте, которые хранятся пока сокет существует. 

В лабораторной работе запросы не зависят друг от друга, следовательно хранить состояние предыдущего запроса от клиента бессмысленно. Значит реализовывать сервер будем опираясь на **stateless** свойство. 

У **stateless** свойства есть свои плюсы: 
1. Легче отлаживать
2. Выше надежность (меньше рассинхронизации)
3. Чем меньше сервер хранит данных, тем меньше злоумышленник может навредить серверу: *resource exhaustion (истощение ресурсов, когда открыто много сессий от одного и того же клиента), подделка чужой сессии или данных, противоречивые запросы, ломающие логику сервера*. 

В Windows для подключения сетевых функций используется библиотека *winsock2.h*, реализация этих функций находится в файле *ws2_32.lib*, поэтому инициализация выглядит так: 

```
#include <WinSock2.h> // библиотека для сетевых функций
#pragma comment(lib, "ws2_32.lib") // сообщение линковщику, о реализации в ws2_32.lib
```

Сама инициализация Winsock (необходима, потому что сеть затрагивает множество компонент,  ресурсов, а следовательно одного объявления заголовка не достаточно) выполняется через функцию `int WSAStartup(WORD wVersionRequested, LPWSADATA lpWSAData);` где:
1. wVersionRequested - версия Winsock. Задается в виде MAKEWORD(number, number). Например: MAKEWORD(2,2) **Макрос `MAKEWORD(a, b)`** на этапе компиляции сам вычисляет и выдаёт готовое значение типа `WORD`
2. lpWSAData - указатель на структуру WSAData, которую Winsock заполнит информацией о реализации Winsock. 
Выключается Winsock функцией `WSACleanup()`. 


Сокет (от англ. гнездо/розетка) - механизм, который позволяет общаться между системами по сети. С точки зрения лабораторной, сокет - дескриптор-число, который привязан к конкретному каналу связи, потому что настоящий сокет находится на уровне kernel space, что не позволяет с ним работать на прямую, только лишь через дескриптор. 

Функция создания сокета выглядит так: 

```
SOCKET WSASocket(
    int af,
    int type,
    int protocol,
    LPWSAPROTOCOL_INFO lpProtocolInfo,
    GROUP g,
    DWORD dwFlags
);
```

1. af (adress family) - семейство адресов, IPv4 или IPv6. Для IPv4 - AF_INET, который нам и потребуется
2. type - тип сокета, SOCK_STREAM - потоковый сокет (TCP), SOCK_DGRAM (UDP) датаграммный сокет
3. protocol - поскольку тип уже все определил (TCP или UDP), тут ставят 0
4. lpProtocolInfo - не нужно, для продвинутых сценариев 
5. g - группа сокетов, используем 0 
6. dwFlags - флаги сокета, создание происходит флагом `WSA_FLAG_OVERLAPPED`, он помечает, что сокет способен к асинхронным операциям. 

Для сетевых функций код ошибки берётся не из возвращаемого значения, а отдельным вызовом — **`WSAGetLastError()`**. Это функция, которая возвращает числовой код последней сетевой ошибки в текущем потоке.

Пример: 

```
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>
#include <WinSock2.h>
#pragma comment(lib, "ws2_32.lib")

int main()
{
	WSAData wsaData;
	int WSAStartupResult = WSAStartup(MAKEWORD(2, 2), &wsaData);
	if (WSAStartupResult != 0)
	{
		printf("WSAStartup failed with error: %d\n", WSAStartupResult);
		return 1;
	}
	printf("WSAStartup succeeded.\n");


	SOCKET listenSocket = WSASocket(AF_INET, SOCK_STREAM, 0, NULL, 0, WSA_FLAG_OVERLAPPED);
	if (listenSocket == INVALID_SOCKET)
	{
		printf("WSASocket failed with error%d\n", WSAGetLastError());
		WSACleanup();
		return 1;
	}
	printf("WSASocket succeeded.\n");


	closesocket(listenSocket);
	WSACleanup();
	return 0; 
}
```

SOCKET - беззнаковый тип (unsigned long long), следовательно проверка (listen_socket == INVALID_SOCKET) - верна, поскольку если сравнивать с -1 (как обычно), то будет сравнение с максимально положительным беззнаковым числом (например 255 для unsigned char). 

После создания сокета, необходимо привязать его к адресу и порту сервера, это выполняется командой `bind()`. 
Порт - отдельный номер сетевого адреса, предназначенный для регулирования принятия данных (чтобы конкретный клиент шел к конкретной программе на сервере). 
Чтобы передать bind конфигурацию сервера, нужно заполнить структуру: 

```
struct sockaddr_in {
    short          sin_family;   // семейство адресов
    unsigned short sin_port;     // порт
    struct in_addr sin_addr;     // IP-адрес
    char           sin_zero[8];  // заполнитель, не используется
};
```

1. sin_family - то же самое, что и при создании сокета (IPv4 - AF_INET)
2. sin_port - собственно порт
3. sin_addr - собственно IP-адрес 

Перед заполнением структуру надо **обнулить целиком**. Это делается `memset(&addr, 0, sizeof(addr));`. 

**Little-endian** («остроконечный с хвоста») — младший байт первым.
**Big-endian** («остроконечный с головы») — старший байт первым. Этот порядок исторически принят **в сети** как стандартный, его называют _сетевым порядком байт_ 
- **`htons`** = **h**ost **to** **n**etwork **s**hort — преобразует 16-битное (короткое, 2 байта) число из хостового порядка в сетевой. **Порт** — 16-битный, поэтому `htons(9000)`
- **`htonl`** = **h**ost **to** **n**etwork **l**ong — то же для 32-битного (длинного, 4 байта) числа. **IP-адрес** — 32-битный, поэтому `htonl(INADDR_ANY)`.
- Есть и обратные функции — `ntohs`, `ntohl`

Функция `int bind(SOCKET s, const struct sockaddr *name, int namelen);`:
1. s - сокет
2. name - структура sockaddr, откуда берется информация 
3. namelen - размер структуры sockaddr (sizeof(sockaddr))

Чтобы сокет начал слушать подключения необходимо использовать функцию `int listen(SOCKET s, int backlog);`: 
1. s - сокет 
2. backlog - размер очереди подключений 

backlog выставим константой SOMAXCONN, которая обозначит системный максимум. backlog напрямую влияет на работу сервера, слишком маленький размер очереди - медленная работа сервера, слишком большой размер - опасность SYN flood атаки.

Нам необходима возможность работать с несколькими клиентами одновременно, иначе есть риск, что слушающий сокет застынет на одном из клиентов. Для этого существует несколько вариантов решений: 
1. Механизмы многопоточности, самый худший вариант, потому что сжигает много ресурсов 
2. *poll* *select* и неблокирующий режим, хороший вариант. Неблокирующий режим переводит слушающий сокет в неблокирующее состояние, когда он не зацикливается на одном клиенте, а через механизмы *poll* или *select* опрашивается массив клиентов на события (основное событие - чтение), чтобы работать только с теми клиентами, которые готовы
3. *IOCP* - порты завершения. С его помощью проверка сокетов отводится на уровень ОС, позволяя программе не останавливаться и не ждать окончания проверки.

*IOCP* (I/O Completion Port) - порты завершения, представляющие собой очередь уведомлений о завершенных любых операциях над сокетами. 
Функция — `CreateIoCompletionPort` создает порт завершения. 

`HANDLE port = CreateIoCompletionPort(INVALID_HANDLE_VALUE, NULL, 0, 0);` создает пустой порт завершения с нуля: 
1. INVALID_HANDLE_VALUE - специальное значение заглушка, которая обозначает, что пока нет привязки сокетов, необходимо только табло
2. NULL - существующего порта нет, нужен новый
3. 0 - ключ 
4. 0 - число потоков обработчиков очереди

Возвращает HANDLE - дескриптор порта. 

`CreateIoCompletionPort((HANDLE)s, port, key, 0);` привязывает сокет к порту завершения. Выполняется для каждого нового сокета. Аргументы остаются прежними. 
**Ключ** (key): число, которое ОС будет возвращать нам вместе с каждым уведомлением по этому сокету. Сюда кладут что-то, что помогает опознать клиента — например, индекс в массиве клиентов, чтобы легко понимать кто выполнил операцию. 

Указатель *OVERLAPPED* используется для того, чтобы отслеживать какая операция произошла. Изначально этот указатель ОС использует в собственных целях , например для контроля переданных байт. Раз указатель использовался для контроля, то принято решение использовать ее как отметку операций, в которой мы можем записать интересующие нас данные. 

```
struct client_ctx {
    SOCKET socket;
    char buf_recv[...];
    char buf_send[...];
    OVERLAPPED overlap_recv;   // бланк для операции чтения
    OVERLAPPED overlap_send;   // бланк для операции отправки
    OVERLAPPED overlap_cancel; // бланк для операции отмены
    ...
};
```

`HANDLE` — общий тип дескриптора WinAPI. 

```
HANDLE hCompletionPort = CreateIoCompletionPort(INVALID_HANDLE_VALUE, NULL, 0, 0);
if (hCompletionPort == NULL)
{
	printf("CreateIoCompletionPort failed with error: %d\n", GetLastError()); // getlasterror тк функция WIN API
	closesocket(listenSocket);
	WSACleanup();
	return 1;
}

CreateIoCompletionPort((HANDLE)listenSocket, hCompletionPort, 0, 0);
```

После создания порта завершения, нужно вызвать интересующую нас операцию - принятие клиента. 
В асинхронном сервере выполняется через функцию *AcceptEx*. В отличие от синхронной функции *accept*, которая даже при неблокирующем режиме работы требует постоянного опроса через цикл while, *AcceptEx* достаточно лишь одного вызова, чтобы ОС сообщила об операции, следовательно программа работает быстрее и может перейти к другим строкам кода. 
Также в *accept* по мере подключения клиентов создавался сокет, в *AcceptEx* требуется изначальная инициализация сокета. 
Также для использования *AcceptEX* нужно инициализировать заголовок *mswsockh*, реализация которого находится в *mswsock.lib*. 

Каждого подключенного клиента нужно хранить в определенной структуре. То есть, хранить его данные, данные, которые нужно отправить клиенту обратно, флаги, структуры *OVERLAPPED*. Следовательно образовывается массив структур клиентов, где индекс в массиве есть ключ для *IOCP*. 

```
#define MAX_CLIENTS 100
typedef struct CLIENT_CONTEXT
{
	SOCKET socket;
	OVERLAPPED overlapped_recv;
	OVERLAPPED overlapped_send;
	OVERLAPPED overlapped_cancel;
	char buffer_recv[512];
	char buffer_send[512];
	unsigned long bytes_received;
	unsigned long bytes_sent;
	unsigned long bytes_send_total; 
	DWORD flags_WSA_recv;
} CLIENT_CONTEXT;

CLIENT_CONTEXT array_clients[MAX_CLIENTS+1];
```

Прототип *AcceptEx* выглядит так: 

```
BOOL AcceptEx(
    SOCKET       sListenSocket,
    SOCKET       sAcceptSocket,
    PVOID        lpOutputBuffer,
    DWORD        dwReceiveDataLength,
    DWORD        dwLocalAddressLength,
    DWORD        dwRemoteAddressLength,
    LPDWORD      lpdwBytesReceived,
    LPOVERLAPPED lpOverlapped
);
```

1. sListenSocket - слушающий сокет (listenSocket). 
2. sAcceptSocket - сокет клиента
3. lpOutputBuffer - буфер, в который записывается локальный и удаленный адрес (сервера и клиента), а также, опционально, первые данные
4. dwReceiveDataLength - сколько данных клиента принять после подключения. Ставим 0, потому что, иначе *AcceptEx* будет ждать передачи данных, которая может зависнуть и бесконечно использовать ресурс. Данные читать будем отдельно, через *WSARecv*
5. dwLocalAddressLength - размер локального адреса + 16
6. dwRemoteAddressLength - размер удаленного адреса + 16
7. lpdwBytesReceived - указатель куда записать количество полученных байт
8. lpOverlapped - указатель на структуру Overlapped 

Перед началом *AcceptEx* нужно обнулить *Overlapped*. 

Реализация функции *schedule_accept* выглядит так: 

```
void schedule_accept()
{
	SOCKET sClient = WSASocket(AF_INET, SOCK_STREAM, 0, NULL, 0, WSA_FLAG_OVERLAPPED); // создаем сокет клиента 
	if (sClient == INVALID_SOCKET)
	{
		printf("WSASocket failed with error: %d\n", WSAGetLastError());
		return;
	}
	acceptedSocket = sClient; // копируем в глобальный сокет, для работы в других функциях
	memset(&array_clients[0].overlapped_recv, 0, sizeof(OVERLAPPED));
	if (!AcceptEx(array_clients[0].socket, acceptedSocket, array_clients[0].buffer_recv, 0, sizeof(sockaddr_in) + 16, sizeof(sockaddr_in) + 16,NULL, &array_clients[0].overlapped_recv))
	{
		int err = WSAGetLastError();
		if (err != ERROR_IO_PENDING)
		{
			printf("AcceptEx failed with error: %d\n", err);
			closesocket(acceptedSocket);
		}
	}
}
```

`GetQueuedCompletionStatus` — разбор параметров, эта функция достает из очереди завершенного порта завершенное уведомление. 

```
BOOL GetQueuedCompletionStatus(
    HANDLE       CompletionPort,
    LPDWORD      lpNumberOfBytesTransferred,
    PULONG_PTR   lpCompletionKey,
    LPOVERLAPPED *lpOverlapped,
    DWORD        dwMilliseconds
);
```

1. CompletionPort - IOCP порт
2. lpNumberOfBytesTransferred - количество байт перенесенных после завершения операции (сколько прочитано/отправлено).
3. lpCompletionKey - адрес переменной, куда запишется key 
4. lpOverlapped - адрес указателя, куда запишется указатель на OverLapped. 
5. dwMilliseconds - сколько ждать, если очередь пуста

Есть **три** возможных исхода:
1. **`TRUE`** — уведомление получено, операция завершилась успешно.
2. **`FALSE`, но `lpOverlapped != NULL`** — уведомление получено, НО сама операция завершилась **с ошибкой** (например, клиент оборвал соединение).
3. **`FALSE` и `lpOverlapped == NULL`** — вот это значит «за отведённое время (`dwMilliseconds`) ничего не пришло» — таймаут, очередь пуста.

Цикл выглядит следующим образом:

```
DWORD bytesTransferred;
ULONG_PTR key;
OVERLAPPED* lpOverlapped;
schedule_accept();
while (TRUE)
{
	bool status = GetQueuedCompletionStatus(hCompletionPort, &bytesTransferred, &key, &lpOverlapped, INFINITE);
	if (lpOverlapped == NULL)
	{
		continue;
	}
	printf("event: key=%llu, bytes=%lu\n", (unsigned long long)key, bytesTransferred);
	if (key == 0)
	{
		printf("new connection accepted\n");
		schedule_accept();
	}
}
```

После принятия подключения нужно найти свободное место в массиве клиентов, привязать сокет к порту завершения и заказать чтение. 

```
void add_accept_connection()
{
	bool status = false; 
	int idx = 0;
	for (int i = 1; i <= MAX_CLIENTS; i++)
	{
		if (array_clients[i].socket == 0)
		{
			array_clients[i].socket = acceptedSocket;
			status = true;
			idx = i;
			printf("New client connected, assigned to slot %d\n", i);
			break;
		}
	}
	if (!status)
	{
		printf("Failed to add new client connection.\n");
		closesocket(acceptedSocket);
		return;
	}
	CreateIoCompletionPort((HANDLE)acceptedSocket, hCompletionPort, (ULONG_PTR)idx, 0);


	//schedule_read(i);
}
```


Реализация функции чтения из клиента, `schedule_read()`, будет копировать содержимое в буфер клиента. 
*WSABUF* - описание буфера, функции *WSARecv* и *WSASend* принимают буфер не на прямую, а через структуру *WSABUF*: 

```
typedef struct _WSABUF {
    ULONG len;    // длина буфера (сколько байт в нём помещается)
    CHAR* buf;    // указатель на сам буфер
} WSABUF;
```

Эта структура необходима, из за того, что *WINSock* умеет работать сразу с несколькими клиентами, соответственно и записывать буфер. 

*WSARecv*: 

```
int WSARecv(
    SOCKET                             s,
    LPWSABUF                           lpBuffers,
    DWORD                              dwBufferCount,
    LPDWORD                            lpNumberOfBytesRecvd,
    LPDWORD                            lpFlags,
    LPWSAOVERLAPPED                    lpOverlapped,
    LPWSAOVERLAPPED_COMPLETION_ROUTINE lpCompletionRoutine
);
```

1. **`s`** — сокет клиента: `array_clients[idx].socket`
2. **`lpBuffers`** — адрес нашего `WSABUF`
3. **`dwBufferCount`** — сколько буферов в массиве.
4. **`lpNumberOfBytesRecvd`** — указатель, куда записать число принятых байт.
5. **`lpFlags`** — указатель на переменную флагов.
6. **`lpOverlapped`** — OVERLAPPED для операции чтения
7. **`lpCompletionRoutine`** — альтернативный механизм уведомления (через callback) - NULL. 

`WSARecv` возвращает `0` при немедленном успехе или `SOCKET_ERROR`

Сама же функция запроса чтения выглядит так: 

```
void schedule_read(int idx)
{
	WSABUF wsaBuf;
	wsaBuf.buf = array_clients[idx].buffer_recv + array_clients[idx].bytes_received;
	wsaBuf.len = sizeof(array_clients[idx].buffer_recv) - array_clients[idx].bytes_received;
	

	array_clients[idx].flags_WSA_recv = 0;
	memset(&array_clients[idx].overlapped_recv, 0, sizeof(OVERLAPPED));

	if (WSARecv(array_clients[idx].socket, &wsaBuf, 1, NULL, &array_clients[idx].flags_WSA_recv, &array_clients[idx].overlapped_recv, NULL) == SOCKET_ERROR)
	{
		if (WSAGetLastError() != ERROR_IO_PENDING)
		{
			printf("WSARecv failed with error: %d\n", WSAGetLastError());
			return;
		}
	}
}
```


Функция отправки данных клиенту, выглядит похожим образом:

```
void schedule_write(int idx)
{
	WSABUF wsaBuf;
	wsaBuf.buf = array_clients[idx].buffer_send + array_clients[idx].bytes_sent;
	wsaBuf.len = array_clients[idx].bytes_send_total - array_clients[idx].bytes_sent;

	memset(&array_clients[idx].overlapped_send, 0, sizeof(OVERLAPPED));

	if (WSASend(array_clients[idx].socket, &wsaBuf, 1, NULL, 0,
		&array_clients[idx].overlapped_send, NULL) == SOCKET_ERROR)
	{
		int err = WSAGetLastError();
		if (err != ERROR_IO_PENDING)
			printf("WSASend failed with error: %d\n", err);
	}
}
```

*WSASend* берет данные из буфера для отправки, противоположная функция функции *WSARecv*.

void get_os_version(char* out, int out_size)
{
	OSVERSIONINFOA osvi;
	memset(&osvi, 0, sizeof(osvi));
	osvi.dwOSVersionInfoSize = sizeof(osvi);

	if (!GetVersionExA(&osvi)) {
		sprintf_s(out, out_size, "Failed to get OS version\n");
		return;
	}

	// сопоставляем номера версии с названием (таблица из методички)
	const char* name = "Unknown Windows";
	if (osvi.dwMajorVersion == 6 && osvi.dwMinorVersion == 1) name = "Windows 7";
	else if (osvi.dwMajorVersion == 6 && osvi.dwMinorVersion == 2) name = "Windows 8 (or newer)";
	else if (osvi.dwMajorVersion == 6 && osvi.dwMinorVersion == 3) name = "Windows 8.1";
	else if (osvi.dwMajorVersion == 10) name = "Windows 10/11";
	else if (osvi.dwMajorVersion == 5 && osvi.dwMinorVersion == 1) name = "Windows XP";

	// разрядность: проверяем, 64-битная ли система
	SYSTEM_INFO si;
	memset(&si, 0, sizeof(si));
	GetNativeSystemInfo(&si);   // именно Native — даёт реальную разрядность даже для 32-битного процесса
	const char* arch = (si.wProcessorArchitecture == PROCESSOR_ARCHITECTURE_AMD64)
		? "x64" : "x86";

	sprintf_s(out, out_size,
		"OS type: %s\nVersion: %lu.%lu (build %lu)\nArchitecture: %s\n",
		name, osvi.dwMajorVersion, osvi.dwMinorVersion, osvi.dwBuildNumber, arch);
}

void get_time_info(char* out, int out_size)
{
    SYSTEMTIME st;
    GetLocalTime(&st);   // локальное время (GetSystemTime даёт UTC; для показа удобнее локальное)

    ULONGLONG ms = GetTickCount64();   // 64-битная версия: не переполняется через 49 дней, в отличие от GetTickCount
    ULONGLONG sec  = ms / 1000;
    ULONGLONG days = sec / 86400;
    ULONGLONG hrs  = (sec % 86400) / 3600;
    ULONGLONG mins = (sec % 3600) / 60;
    ULONGLONG secs = sec % 60;

    sprintf_s(out, out_size,
        "Current time: %02d:%02d:%02d  %02d.%02d.%04d\r\n"
        "Uptime: %llu days, %llu hours, %llu min, %llu sec\r\n",
        st.wHour, st.wMinute, st.wSecond, st.wDay, st.wMonth, st.wYear,
        days, hrs, mins, secs);
}

void get_disks_info(char* out, int out_size)
{
    out[0] = '\0';                          // начинаем с пустой строки
    DWORD drives = GetLogicalDrives();      // битовая маска: бит 0 = диск A, бит 1 = B, ...

    for (int i = 0; i < 26; i++)
    {
        if (!((drives >> i) & 1)) continue; // этого диска нет — пропускаем

        char root[4] = { (char)('A' + i), ':', '\\', '\0' };  // "C:\"

        // тип диска
        UINT type = GetDriveTypeA(root);
        const char* typeStr;
        switch (type) {
            case DRIVE_FIXED:     typeStr = "Local";     break;
            case DRIVE_REMOVABLE: typeStr = "Removable"; break;
            case DRIVE_REMOTE:    typeStr = "Network";   break;
            case DRIVE_CDROM:     typeStr = "CD-ROM";    break;
            default:              typeStr = "Unknown";   break;
        }

        // файловая система (NTFS/FAT32/...)
        char fsName[16] = "";
        GetVolumeInformationA(root, NULL, 0, NULL, NULL, NULL, fsName, sizeof(fsName));

        char line[64];
        sprintf_s(line, sizeof(line), "%s  %-9s  FS: %s\r\n", root, typeStr, fsName);
        strcat_s(out, out_size, line);      // дописываем строку к общему ответу
    }
}

void get_disk_space_info(char* out, int out_size)
{
    out[0] = '\0';
    DWORD drives = GetLogicalDrives();

    for (int i = 0; i < 26; i++)
    {
        if (!((drives >> i) & 1)) continue;

        char root[4] = { (char)('A' + i), ':', '\\', '\0' };

        if (GetDriveTypeA(root) != DRIVE_FIXED) continue;  // только локальные (требование методички)

        ULARGE_INTEGER freeBytes, totalBytes;
        if (GetDiskFreeSpaceExA(root, &freeBytes, &totalBytes, NULL))
        {
            char line[80];
            sprintf_s(line, sizeof(line), "%s  free: %llu MB / total: %llu MB\r\n",
                root,
                freeBytes.QuadPart / (1024 * 1024),
                totalBytes.QuadPart / (1024 * 1024));
            strcat_s(out, out_size, line);
        }
    }
}
