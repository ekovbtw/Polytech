**Сервер** — тот, кто пассивно _слушает_ порт и ждёт входящих подключений (`listen`).
**Клиент** — тот, кто активно _устанавливает_ соединение (`connect`).
Порядок соединения: 
1. Клиент инициализирует соединение, отправляя запрос серверу
2. Сервер постоянно находится в слушающем состоянии, потому что клиент не способен запустить сервер самостоятельно

Необходимо использовать шифрование данных, проверку формата и аналогичные методы обеспечения безопасности, для защиты работоспособности сервера и целостности данных. 

**state** - состояние, которое сервер запоминает, чтобы использовать в будущих запросах от одного и того же клиента. 
**stateless** и **statefull** - свойство архитектуры сервера, проектное решение. **stateless** - свойство, при котором сервер не запоминает состояние клиентов. **statefull** - противоположное свойство, запоминающее состояние клиентов.   

**statefull** например запоминает: 
1. Факт аутентификации: к примеру, клиент ввел данные для аутентификации пару минут назад, следовательно, сервер не запрашивает их повторно. Так работают сессии на сайтах (session-куки). 
2. Прогресс многошаговой операции: например, сохранение корзины в онлайн-магазине
3. Количество блоков данных принятых от клиента (для корректности работы протокола)
4. Накопленные настройки сессии (например, настройка на перевод на русский язык сайтов)

*IP и PORT* - не являются компонентами свойства **statefull**, это базовые данные о клиенте, которые хранятся пока сокет существует. 

В лабораторной работе запросы не зависят друг от друга, следовательно хранить состояние предыдущего запроса от клиента бессмысленно. Значит реализовывать сервер будем опираясь на **stateless** свойство. 

У **stateless** свойства есть свои плюсы: 
1. Легче отлаживать
2. Выше надежность (меньше рассинхронизации)
3. Чем меньше сервер хранит данных, тем меньше злоумышленник может навредить серверу: *resource exhaustion (истощение ресурсов, когда открыто много сессий от одного и того же клиента), подделка чужой сессии или данных, противоречивые запросы, ломающие логику сервера*. 

В Windows для подключения сетевых функций используется библиотека *winsock2.h*, реализация этих функций находится в файле *ws2_32.lib*, поэтому инициализация выглядит так: 

```
#include <WinSock2.h> // библиотека для сетевых функций
#pragma comment(lib, "ws2_32.lib") // сообщение линковщику, о реализации в ws2_32.lib
```
