# ПАТЧИНГ
Первое определение, которое стоит дать: патчинг. 
**Патчинг** - изменение байт в уже скомпилированном файле. Осуществляется без исходного кода, с целью обойти защиту. 

Напишем простую программу проверки пароля: 

```
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

void programm()
{
	printf("Welcome to the program!\n");
	return;
}

int main() 
{
	FILE* file = fopen("password.txt", "r");
	if (file == NULL)
	{
		printf("Error opening password file.\n");
		exit(1);
	}

	char password[100];
	if (fgets(password, sizeof(password), file) == NULL)
	{
		printf("Error reading password file.\n");
		fclose(file);
		exit(1);
	}
	
	int password_length = strlen(password);
	if (password[password_length - 1] == '\n')
	{
		password[password_length - 1] = '\0';
		password_length--;
	}

	printf("Password read from file: %s\n", password);

	const char* real_password = "secret123";

	if (strcmp(password, real_password) == 0)
	{
		FILE* out = fopen("serial.txt", "w");
		if (out == NULL)
		{
			printf("Error opening output file.\n");
			fclose(file);
			exit(1);
		}
		else
		{
			fprintf(out, "KEY$%010d$\n", 1234567890);
			fclose(out);
		}
		printf("Password is correct.\n");
		programm();
	}
	else
	{
		printf("Password is incorrect.\n");
	}

	fclose(file);
	return 0;
}
```

Цель *патчинга* - найти условный переход (ветка strcmp), зависящий от результата проверки пароля, удалить его или инвертировать. Правка происходит по машинным байтам в файле. 

Поиск проходит так: 
1. загрузить release .exe 
2. ctrl+g: TRIPO1.exe
3. поиск по всем модулям: строковые ссылки
4. фильтр

![[Pasted image 20261026161431.png]]

Ключевыми моментами являются: 

```
7FF76C671188   lea rdx, [..."secret123"]      ← кладём адрес эталона "secret123"
7FF76C67118F   lea rcx, [rsp+20]              ← кладём адрес прочитанного пароля
7FF76C671194   call <tripo1.strcmp>           ← ВЫЗОВ strcmp(пароль, "secret123")
7FF76C671199   test eax, eax                  ← проверяем результат: eax == 0 ?
7FF76C67119B   jne tripo1.7FF76C67120D        ← если НЕ равно (пароль неверный) → прыжок
```

Наша цель - убрать этот переход. Это можно сделать удалением инструкции jne (*jump if not equal*) на *nop*. Видно, что инструкция *jne* занимает 2 байта (75 70), а *nop* - 1 байт, следовательно, нужно добавить *nop* два раза. 

Нажимаем правой кнопкой мыши по строке: заполнить NOP.

# ЗАЩИТА
Защита исходного кода позволяет обезопасить от взлома программу.
## ШИФРОВАНИЕ СТРОК
В разделе *ПАТЧИНГ* легко было найдено место обработки корректности пароля, с помощью строк: "Password correct" и подобных. Чтобы злоумышленнику было сложнее найти место обработки пароля используют шифрование строк. 
В данной лабораторной используется **XOR шифрование** - каждый байт строки XOR с ключом. 
Плюс такого шифрования, что один и тот же ключ шифрует и расшифровывает: *A xor K = B* и *B xor K = A*. 
Минус такого шифрования состоит в том, что при использовании строки исполняющим файлом она расшифровывается и злоумышленник, поставив точку останова после выполнения строки, увидит расшифровку. Поэтому одного такого метода недостаточно. 

```
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>
#include <string.h>

void encrypt_and_print(const char* name, const char* text, unsigned char key)
{
    size_t len = strlen(text);
    printf("unsigned char %s[] = { ", name);
    for (size_t i = 0; i < len; i++)
        printf("0x%02X, ", (unsigned char)text[i] ^ key);
    printf("0x%02X };  // \"%s\"\n", key, text);  
}

int main()
{
    unsigned char key = 0x5A;
    encrypt_and_print("enc_password", "secret123", key);
    encrypt_and_print("enc_success", "Password is correct.", key);
    encrypt_and_print("enc_welcome", "Welcome to the program!", key);
    encrypt_and_print("enc_fail", "Password is incorrect.", key);
    return 0;
}
```
Утилита для шифрования текста ключом 0x5A. 

## АНТИ-ОТЛАДКА
Во время отладки ОС представляет отладчику специальные системные интерфейсы: **ptrace** в Linux и **DebugActiveProcess** - Windows. 
Четыре метода, которые помогают реализовать анти-отладочную защиту: 
1. IsDebuggerPresent - спросить ОС напрямую является ли ОС родителем процесса и следит ли она за ним
2. Чтение флага в **PEB**, process enviroment block (структура каждого процесса в Windows), вручную (PEB.BeingDebugger)
3. CheckRemoteDebuggerPresent - системный механизм (API), который ловит внешние отладчики
4. Тайминговая проверка - под отладчиком время выполнения программы дольше

### IsDebuggerPresent
`IsDebuggerPresent` внутри читает один флаг (`BeingDebugged`) из структуры *PEB*. Реализация ниже:

```
void anti_debug_1()
{
	if (IsDebuggerPresent())
	{
		printf("Debugger detected. Exiting.\n");
		exit(1);
	}
}
```

Слабость такого метода, что это обычная функция: злоумышленник может поставить точку останова и в момент возврата поменять значение с единицы на ноль. Можно также пропатчить сам флаг *PEB*.

При отладке программа закрывается со статусом 0x1. 

### РУЧНОЕ ЧТЕНИЕ ФЛАГА ИЗ PEB
На x64 адрес PEB хранится в сегментном регистре `GS` по смещению `0x60`. А внутри PEB байт `BeingDebugged` — по смещению `0x02`. Это фиксированные, документированные смещения для x64 Windows.

```
void anti_debug_2()
{
	PPEB peb = (PPEB)__readgsqword(0x60);
	if (peb->BeingDebugged)
	{
		printf("Debugger detected (PEB). Exiting.\n");
		exit(2); 
	}
}
```

`__readgsqword(0x60)` — это **intrinsic**, встроенная в компилятор MSVC функция, которая компилируется в одну ассемблерную инструкцию чтения из `GS:[0x60]`.

### CheckRemoteDebuggerPresent
Способ отследить отладчик внутри ОС. Так как ОС дает специальные системные интерфейсы для слежки за .exe, то можно их обнаружить. Remote в данном контексте используется, не как сеть, а как внешний доступ внутри ОС. 

```
void anti_debug_3()
{
	BOOL present = FALSE;
	CheckRemoteDebuggerPresent(GetCurrentProcess(), &present);
	if (present)
	{
		printf("Debugger detected (remote). Exiting.\n");
		exit(3);
	}
}
```


### Тайминговая проверка 
Можно замерить время исполнения .exe и на основе значения времени сделать вывод: следит ли отладчик за программой. Если время получается подозрительно большим, значит работает отладчик. 

```
void anti_debug_4()
{
	DWORD start = GetTickCount();
	for (volatile int i = 0; i < 1000; i++) {}
	DWORD elapsed = GetTickCount() - start;
	if (elapsed > 100) 
	{
		printf("Debugger detected (timing). Exiting.\n");
		exit(4);
	}
}
```

## АНТИ-ВМ
Логика проверки состоит в том, что человек, пытающийся изучить программу в виртуальной среде, не сможет запустить .exe. Программа будет думать, что ее изучают и блокироваться. 
Виртуальные машины оставляют характерные записи: например в описании дисков могут оставить текст "VBOX" или "VMware". Могут оставить следы в MAC-адресах и тому подобное. 

### Описание в редакторе реестра

```
int check_registry_vm()
{
	HKEY hKey;
	char buffer[256];
	DWORD size = sizeof(buffer);

	// ключ с описанием системного диска
	if (RegOpenKeyExA(HKEY_LOCAL_MACHINE,
		"HARDWARE\\DESCRIPTION\\System\\BIOS", 0, KEY_READ, &hKey) == ERROR_SUCCESS)
	{
		if (RegQueryValueExA(hKey, "SystemManufacturer", NULL, NULL,
			(LPBYTE)buffer, &size) == ERROR_SUCCESS)
		{
			RegCloseKey(hKey);
			if (strstr(buffer, "VMware") || strstr(buffer, "VirtualBox") ||
				strstr(buffer, "VBOX") || strstr(buffer, "innotek"))
				return 1; 
		}
		else RegCloseKey(hKey);
	}
	return 0;   
}
```

Сначала открываем директорию в реестре: HARDWARE
