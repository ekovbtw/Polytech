2.1 Полезная нагрузка 
Программа подсчитывает число вариантов расстановки знаков «+» и «−» 
между N числами, при которых получается заданная сумма. Первое число ис-

записываются число потоков, N и число решений, в time.txt – время вычислений.

3 РЕАЛИЗАЦИЯ ЗАЩИТНЫХ МЕХАНИЗМОВ 
3.1 Связь защит с состоянием программы 
Большинство защит изменяет глобальную переменную g_seed через cor-
rupt_seed. Исходное значение равно 0xDEADBEEF. От неё зависят ключ расшиф-
ровки сообщений, формирование серийного номера и целевая сумма в рабочих 
потоках. Поэтому обнаружение анализа может проявиться позже в виде нечита-
емых сообщений, неверного номера или неправильного результата вычислений. 
IsDebuggerPresent обрабатывается отдельно: программа сразу завершается с ко-
дом 1.

3.2 Шифрование строк 
Пароль и основные диагностические сообщения хранятся в массивах бай-
тов, закодированных XOR с ключом 0x5A. Операция обратима: повторное при-
менение того же ключа восстанавливает исходный байт. str_key получает 0x5A 
из младшего байта исходного g_seed: EF XOR B5 = 5A. При изменении состояния 
сообщения расшифровываются неправильно. Утилита xor_encrypt.cpp генери-
рует массивы для включения в основной код. 
Листинг 4 – Расшифровка массива байтов 
void decrypt(const unsigned char* enc, int len, unsigned char key, char* out) 
{ 
    for (int i = 0; i < len; i++) 
        out[i] = enc[i] ^ key; 
    out[len] = '\0'; 
}

3.5 Контроль целостности и повторные проверки 
verify_integrity вычисляет CRC32 байтов функции check_password_crc до 
функции-маркера marker_crc. Для сохранённого EXE начало имеет RVA 0x1930, 
маркер – 0x1970, длина участка – 64 байта. Независимый пересчёт дал 
0xF5D709B8, совпадающий с эталоном в коде. При несовпадении меняется 
g_seed. 
Листинг 11 – Проверка целостности функции пароля 
void verify_integrity() 
{ 
    unsigned char* start = (unsigned char*)check_password_crc; 
    unsigned char* end = (unsigned char*)marker_crc; 
    int len = (int)(end - start); 
    if (len <= 0 || len > 4096) return; 
    unsigned int current = crc32(start, len); 
    if (current != 0xF5D709B8) 
        corrupt_seed(); 
} 
 
CRC32 не является криптографическим хешем и допускает коллизии. Рас-
положение функций определяется компилятором и компоновщиком, поэтому 
границы и эталон привязаны к сборке. При некорректной длине текущая реали-
зация пропускает проверку. В бинарном обходе изменялись вызывающие ветки, 
а не контролируемая функция, поэтому её CRC оставалась прежней. 
Основная проверка выполняется в main, повторная – в programm через ver-
ify_password_again. Между ними распределены проверки среды и формирование 
номера. Ложная ветка strlen(password) == 999 расположена после чтения пароля; 
при буфере 100 байтов такое условие недостижимо и может быть устранено оп-
тимизатором.

4.1 Получение серийного номера из пароля 
Серийный номер вычисляется алгоритмом FNV-1a с 32-битным беззнако-
вым накопителем. Каждый байт пароля смешивается XOR, затем результат 
умножается на 16777619 по модулю 2^32. Для secret123 получено 831623743, или 
0x3191923F. Формат %010 u дополняет десятичное значение нулём слева: 
KEY$0831623743$. FNV-1a используется для учебного отображения пароля в 
номер, а не для безопасного хранения паролей. 
Листинг 14 – Вычисление серийного номера 
unsigned int serial_from_password(const char* password) 
{ 
    unsigned int hash = 2166136261u; 
 
    for (const unsigned char* p = (const unsigned char*)password; *p != '\0'; ++p) 
    { 
        hash ^= *p; 
        hash *= 16777619u; 
    } 
 
    return hash; 
} 
 
После хеширования номер смешивается с g_seed XOR DEADBEEF. При 
нормальном состоянии эта маска равна нулю. Затем вычитается 4, а ASM-
функции прибавляют 1 и 3, сохраняя исходный результат и включая антидизас-
семблерные фрагменты в вычисление номера. 
4.2 Изменение инструкции сравнения 
В ASM-функции serial_check сравнивается ECX с непосредственной 32 -
битной константой. Начало команды cmp ecx, imm32 имеет байты 81 F9. Эталон 
0x3191923F хранится в порядке little-endian как 3F 92 91 31. В EXE эти четыре 
байта предварительно закодированы XOR AA и равны 95 38 3 B 9B. Метка se-
rial_check_value указывает внутрь инструкции, на изменяемую константу.

4.3 Обход самомодифицирующейся проверки 
В эксперименте на входе serial_check находился номер ECX = 0x8597F352, 
не совпадающий с эталоном 0 x3191923F. После cmp флаг ZF был равен 0. До 
выполнения sete al флаг вручную изменён на 1. Затем sete al и movzx eax, al сфор-
мировали EAX = 1. Таким образом, функция сообщила об успехе при несовпада-
ющем номере. Это обход в текущем процессе, не изменение файла на диске и не 
исправление самого номера.

7 ВЫВОДЫ 
В ходе работы исследованы бинарный патчинг и взаимосвязанные защит-
ные механизмы. Реализованы проверки отладки и виртуальной среды, контроль

запутывание потока управления и самомодифицирующееся сравнение серийного 
номера. Показано, что подмена флага результата позволяет обойти сравнение 
даже после динамического восстановления инструкции. 
Для защищённой версии получен сохранённый патч, который при невер-
ном пароле формирует правильный серийный номер и сохраняет корректный ре-
зультат полезных вычислений. Эксперимент показал необходимость контроли-
ровать общее состояние программы, а не только ве тку отказа. Упаковка UPX 
уменьшила размер файла, повысила энтропию и изменила точку входа; исходная 
точка входа найдена после распаковки и подтверждена сравнением байтов. 
Ограничения версии: шифрование строк неполное; отдельно не подтвер-
ждён третий метод некорректного дизассемблирования; проверка отладочных 
регистров требует доработки; границы CRC зависят от компоновки. Эти ограни-
чения не отменяют полученные результаты, но не позволяют считать защиту 
полной или неуязвимой.
