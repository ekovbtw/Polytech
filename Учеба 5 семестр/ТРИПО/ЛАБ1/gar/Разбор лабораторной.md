# g_seed

```
// global seed for key generation
volatile unsigned int g_seed = 0xDEADBEEF;

static unsigned char str_key(void)
{
	return (unsigned char)((g_seed & 0xFF) ^ 0xB5);
}

static void corrupt_seed(void)
{
	g_seed = g_seed * 1664525u + 1013904223u;
}
//
```
g_seed - переменная, которая использовалась, чтобы запутать патчинг программы. При некоторых проверках (анти-отладке, анти-вм) вызывался corrupt_seed, которая ломала g_seed. Сломанный g_seed ломал вычисления, серийный номер или неправильно расшифровывал строки (смотря на каком этапе переменная была сломана).

# anti_debug1

```
void anti_debug_1()
{
    if (IsDebuggerPresent())
    {
        print_enc(enc_dbg1, sizeof(enc_dbg1) - 1);
        printf("\n");
        exit(1);
    }
}
```

IsDebuggerPresent - WinAPI функция, позволяющая понять находится ли исполняемый файл под отладкой. Возвращает 1, если отладчик обнаружен, и 0, если нет.

# PEB.BeingDebugged

```
void anti_debug_2()
{
    PPEB peb = (PPEB)__readgsqword(0x60);

    if (peb->BeingDebugged)
    {
        corrupt_seed();
    }
}
```

PEB (Process Environment Block) - специальная структура Windows процесса. Одно из полей структуры BeingDebugged показывает находится ли процесс под отладкой.

# CheckRemoteDebuggerPresent

```
void anti_debug_3()
{
    BOOL present = FALSE;
    CheckRemoteDebuggerPresent(GetCurrentProcess(), &present);

    if (present)
    {
        corrupt_seed();
    }
}
```

CheckRemoteDebuggerPresent - функция WinAPI, которая по дескриптору процесса определяет находится ли он под отладкой, получает сведения из DebugPort. Записывает результат в present.

# тайминговая проверка

```
void anti_debug_4()
{
    DWORD start = GetTickCount();

    for (volatile int i = 0; i < 1000; i++) {}

    DWORD elapsed = GetTickCount() - start;

    if (elapsed > 100)
    {
        corrupt_seed();
    }
}
```

# аппаратные точки останова

```
void anti_debug5()
{
    CONTEXT ctx;
    memset(&ctx, 0, sizeof(ctx));
    ctx.ContextFlags = CONTEXT_DEBUG_REGISTERS;

    if (GetThreadContext(GetCurrentThread(), &ctx))
    {
        if (ctx.Dr0 != 0 || ctx.Dr1 != 0 ||
            ctx.Dr2 != 0 || ctx.Dr3 != 0)
        {
            corrupt_seed();
        }
    }
}
```

В отличие от программной точки останова, которые используют инструкцию INT3 0xCC, аппаратные точки останова используют специальные отладочные регистры процессора. 
Регистры DR0-DR3 могут содержать адреса, за которыми процессор должен следить. 

# check_registry_vm()

```
if (RegOpenKeyExA(
    HKEY_LOCAL_MACHINE,
    "HARDWARE\\DESCRIPTION\\System\\BIOS",
    0,
    KEY_READ,
    &hKey) == ERROR_SUCCESS)
{
    // Чтение SystemManufacturer
}
```

Здесь программа обращается к реестру Windows. Программа читает значение SystemManufacturer и ищем характерные строки: 
"VMware", "VirtualBox", "VBOX", "innotek". 
При запуске Windows система получает сведения об оборудовании. В виртуальной среде гипервизор эмулирует оборудование и может предоставится системой производства VmWare.
