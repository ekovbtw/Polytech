# g_seed

```
// global seed for key generation
volatile unsigned int g_seed = 0xDEADBEEF;

static unsigned char str_key(void)
{
	return (unsigned char)((g_seed & 0xFF) ^ 0xB5);
}

static void corrupt_seed(void)
{
	g_seed = g_seed * 1664525u + 1013904223u;
}
//
```
g_seed - переменная, которая использовалась, чтобы запутать патчинг программы. При некоторых проверках (анти-отладке, анти-вм) вызывался corrupt_seed, которая ломала g_seed. Сломанный g_seed ломал вычисления, серийный номер или неправильно расшифровывал строки (смотря на каком этапе переменная была сломана).

# CheckRemoteDebuggerPresent

```
void anti_debug_3()
{
    BOOL present = FALSE;
    CheckRemoteDebuggerPresent(GetCurrentProcess(), &present);

    if (present)
    {
        corrupt_seed();
    }
}
```

CheckRemoteDebuggerPresent - функция WinAPI, которая по дескриптору процесса определяет находится ли он под отладкой, получает сведения из DebugPort. Записывает результат в present.

# аппаратные точки останова

На уровне внутренних структур Windows встречается поле DebugPort структуры EPROCCESS - внутреннего объекта процесса в ядре. 
В самом EPROCCESS.DebugPort хранится указатель - адрес связанного объекта отладки в памяти ядра: 
```
PVOID DebugPort; // void*
```
Если 
```
DebugPort = NULL;
```
То связанного объекта - нет.
```
DebugPort = FFFF800012340000 // адрес связанного объекта 
```

При подключении отладчика происходит примерный цикл: 

```
while (программа_ещё_работает)
{
    WaitForDebugEvent(...);   // дождаться события

    // Показать регистры, память и инструкции.
    // При необходимости изменить состояние программы.

    ContinueDebugEvent(...); // разрешить продолжение
}
```

Windows предоставляет особые API для работы отладчика с процессом. Например DebugActiveProcess подключает активный процесс к отладчику. После подключения отладчик получает уведомления на события создания потоков, исключений, завершения потоков и процесса. 
При событии отладки Windows приостанавливает потоки отлаживаемого процесса и уведомляет отладчик. Отладчик получает данные в структуре DEBUG_EVENT - описание произошедшего события. 

```
DEBUG_EVENT event = { 0 };

BOOL success = WaitForDebugEvent(&event, INFINITE);
```

В структуре есть три поля: 
dwDebugEventCode - тип события
dwProcessId - ID процесса, где событие произошло 
dwThreadId - ID потока, где событие произошло

и поле *u* - где будут сведения о событии

### Пример
Когда программа делила на ноль: 

```
DEBUG_EVENT
│
├─ dwDebugEventCode = EXCEPTION_DEBUG_EVENT тип событие (исключение)
├─ dwProcessId      = идентификатор 
├─ dwThreadId       = идентификатор выполнявшего деление потока
│
└─ u.Exception
   ├─ ExceptionRecord.ExceptionCode    = 0xC0000094 (причина - деление на ноль)
   ├─ ExceptionRecord.ExceptionAddress = адрес инструкции idiv (адрес инструкции, которая вызвала исключение)
   └─ dwFirstChance                    = 1 (отладчик получил первую возможность обработать исключение)
```




```
void anti_debug5()
{
    CONTEXT ctx;
    memset(&ctx, 0, sizeof(ctx));
    ctx.ContextFlags = CONTEXT_DEBUG_REGISTERS;

    if (GetThreadContext(GetCurrentThread(), &ctx))
    {
        if (ctx.Dr0 != 0 || ctx.Dr1 != 0 ||

        {

        }
    }
}
```

В отличие от программной точки останова, которые используют инструкцию INT3 0xCC, аппаратные точки останова используют специальные отладочные регистры процессора. 
Регистры DR0-DR3 могут содержать адреса, за которыми процессор должен следить.

# CRC32
Вычисление контрольной суммы участка кода

```
void verify_integrity()
{
    unsigned char* start =
        (unsigned char*)check_password_crc;

    unsigned char* end =
        (unsigned char*)marker_crc;

    int len = (int)(end - start);

    if (len <= 0 || len > 4096)
        return;

    unsigned int current = crc32(start, len);

    if (current != 0xF5D709B8)
        corrupt_seed();
}
```

# Серийник зависит от пароля

```
unsigned int serial_from_password(const char* password)
{
    unsigned int hash = 2166136261u;

    for (const unsigned char* p =
         (const unsigned char*)password;
         *p != '\0'; ++p)
    {
        hash ^= *p;
        hash *= 16777619u;
    }

    return hash;
}
```

Вычисляет хэш пароля. Это **FNV-1a** — некриптографическая хеш-функция, последовательно преобразующая входные байты в числовое значение.

```
serial_num ^= (g_seed ^ 0xDEADBEEFu); // маска под g_seed если он корректный 0

serial_num -= 4u;
serial_num = (unsigned int)antidis_add1((int)serial_num);
serial_num = (unsigned int)antidis_jmid((int)serial_num);
```

```
antidis_add1 PROC
    mov eax, ecx         

    xor edx, edx          
    jz  real_code         
    jnz real_code      

    db 0E8h ; добавляем байт, который дизассемблер примет за call                

real_code:
    add eax, 1            
    ret
antidis_add1 ENDP
```
