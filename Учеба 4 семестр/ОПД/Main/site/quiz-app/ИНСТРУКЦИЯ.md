## 1. Структура файлов

```
quiz-app/
│
├── server.js            ← Весь бэкенд (Node.js + Express + SQLite)
├── quiz.db              ← База данных SQLite (создаётся автоматически при первом запуске)
├── package.json         ← Зависимости npm
│
├── start.bat            ← Двойной клик — запускает всё
├── start.ps1            ← PowerShell-скрипт: Node.js + SSH-туннель + watchdog
│
└── public/              ← Всё что отдаётся браузеру
    ├── index.html           ← Главная страница (лендинг)
    ├── auth.html            ← Вход / Регистрация
    ├── dashboard.html       ← Кабинет (разный для учителя и студента)
    ├── create-test.html     ← Создание и редактирование теста
    ├── take-test.html       ← Прохождение теста студентом
    ├── results.html         ← Результаты студента после теста
    ├── test-results.html    ← Результаты теста для учителя (таблица)
    │
    ├── css/
    │   └── style.css        ← Весь CSS (дизайн-система, компоненты, адаптив)
    │
    └── js/
        └── common.js        ← Общий JS: Auth, API, Toast, Navbar, утилиты
```

## 2. Как устроен бэкенд (server.js)

Файл один — `server.js`. Разбит на секции:

### Секции файла

| Строки    | Что делает |
|-----------|------------|
| 1–13      | Подключение библиотек, создание Express-приложения |
| 15–83     | **Создание базы данных** — таблицы создаются при запуске если их нет |
| 86–100    | Утилиты: генерация уникального 6-символьного кода теста |
| 103–118   | **Middleware**: `auth` (проверка JWT-токена), `teacherOnly` (только учитель) |
| 121–178   | **Маршруты AUTH**: регистрация, вход, отметка онбординга |
| 181–286   | **Маршруты TESTS** (для учителя): список, получить, создать, изменить, удалить |
| 289–327   | **Маршруты PUBLIC** (без авторизации): найти тест по коду, получить вопросы |
| 330–393   | **Маршруты SUBMIT**: отправить ответы, получить результат |
| 396–409   | **Маршруты RESULTS**: учитель смотрит все ответы по тесту |
| 412–418   | SPA fallback + запуск сервера на порту 3000 |

### Как защита работает

```
Запрос → auth middleware → проверяет JWT в заголовке Authorization: Bearer <token>
                         → если токен невалиден — 401
                         → если роль не teacher — 403 (teacherOnly)
```

JWT хранится в `localStorage` браузера. Живёт 7 дней.

## 3. Как устроен фронтенд

### common.js — общий модуль (подключён на каждой странице)

```
Auth        — работа с localStorage: getToken(), getUser(), save(), clear(),
              requireAuth(role) — редиректит если не залогинен / не та роль

API         — обёртка над fetch: API.get(url), API.post(url, body),
              API.put(url, body), API.delete(url)
              Автоматически добавляет Authorization: Bearer <token>

showToast() — всплывающее уведомление (зелёное / красное)
showAlert() — ошибка внутри страницы
renderNavbar() — рисует шапку сайта
copyToClipboard() — копирует текст с уведомлением
fmtDate()   — форматирует дату в dd.mm.yyyy hh:mm
scorePillClass() — цвет бейджа оценки (зелёный / жёлтый / красный)
```

### Логика каждой страницы

**auth.html**
- Две вкладки: Вход / Регистрация
- Выбор роли радиокнопками (Студент / Учитель)
- При успехе — сохраняет токен и редиректит на `/dashboard.html`

**dashboard.html**
- Проверяет роль пользователя и показывает разный интерфейс:
  - Учитель: список тестов, кнопки создать/редактировать/результаты/удалить, онбординг-модалка
  - Студент: поле ввода кода теста → переход на `/take-test.html?code=XXXXXX`

**create-test.html**
- Режим создания (`/create-test.html`) или редактирования (`/create-test.html?id=5`)
- Динамически добавляет блоки вопросов и варианты ответов через `createElement`
- Настройки теста: пароль, анонимность, показ результата, перемешивание
- При сохранении показывает код теста

**take-test.html**
- Принимает `?code=XXXXXX` в URL
- Экраны по порядку: ввод пароля (если есть) → ввод имени (если не анонимный) → вопросы → отправка
- После отправки редиректит на `/results.html?id=<submission_id>`

**results.html**
- Показывает счёт студента
- Если учитель включил `show_results` — детальный разбор: какой ответ дал / какой правильный

**test-results.html**
- Только для учителя, принимает `?id=<test_id>`
- Таблица всех попыток: имя, дата, баллы
- Кнопка экспорта в CSV

## 4. База данных

### Расположение файла

```
quiz-app/quiz.db
```

Файл создаётся автоматически при первом запуске `server.js`. Это обычный SQLite-файл.

### Схема таблиц

```
users
  id            — авто ID
  username      — логин (уникальный, без учёта регистра)
  email         — email (уникальный)
  password_hash — хэш пароля bcrypt
  role          — 'teacher' или 'student'
  is_new        — 1 если ещё не прошёл онбординг, 0 после
  created_at    — дата регистрации

tests
  id                — авто ID
  code              — 6-символьный код (напр. "A3KX7P"), уникальный
  title             — название теста
  description       — описание (может быть пустым)
  teacher_id        — ID учителя-владельца → users.id
  password          — пароль к тесту (NULL если без пароля)
  is_anonymous      — 0/1 — не спрашивать имя студента
  show_results      — 0/1 — показывать ли студенту результат
  shuffle_questions — 0/1 — перемешивать вопросы
  created_at / updated_at

questions
  id             — авто ID
  test_id        — → tests.id (при удалении теста — удаляются каскадом)
  question_text  — текст вопроса
  question_order — порядковый номер (0, 1, 2...)

answers
  id          — авто ID
  question_id — → questions.id (каскадное удаление)
  answer_text — текст варианта
  is_correct  — 0/1 — правильный ли вариант

submissions  (одна запись = одно прохождение теста студентом)
  id              — авто ID
  test_id         — → tests.id
  user_id         — → users.id (NULL если студент не залогинен)
  student_name    — имя студента (или 'Аноним')
  score           — кол-во правильных ответов
  total_questions — всего вопросов было
  completed_at    — дата прохождения

submission_answers  (ответы студента на каждый вопрос)
  id            — авто ID
  submission_id — → submissions.id
  question_id   — → questions.id
  answer_id     — → answers.id (NULL если студент не выбрал ответ)
```

### Связи между таблицами

```
users (teacher_id) ──< tests >──< questions >──< answers
                                      │
                   submissions >──────┘
                        │
               submission_answers
```

### Работа с базой данных вручную

#### Просмотр через PowerShell / SQLite CLI

Скачай [DB Browser for SQLite](https://sqlitebrowser.org/) — графический интерфейс для quiz.db.

Или через командную строку (если установлен sqlite3):
```
sqlite3 quiz-app\quiz.db
```

#### Полезные SQL-запросы

```sql
-- Все пользователи
SELECT id, username, email, role, created_at FROM users;

-- Все тесты с количеством вопросов и попыток
SELECT t.id, t.code, t.title,
       COUNT(DISTINCT q.id) AS questions,
       COUNT(DISTINCT s.id) AS submissions
FROM tests t
LEFT JOIN questions q ON q.test_id = t.id
LEFT JOIN submissions s ON s.test_id = t.id
GROUP BY t.id;

-- Результаты конкретного теста (замени 1 на нужный test_id)
SELECT s.student_name, s.score, s.total_questions, s.completed_at
FROM submissions s WHERE s.test_id = 1
ORDER BY s.completed_at DESC;

-- Удалить пользователя по имени
DELETE FROM users WHERE username = 'имя';

-- Сбросить пароль (новый хэш нужно сгенерировать через bcrypt)
UPDATE users SET password_hash = '...' WHERE username = 'имя';

-- Удалить все результаты по тесту
DELETE FROM submissions WHERE test_id = 1;

-- Удалить тест полностью (вопросы и ответы удалятся каскадом)
DELETE FROM tests WHERE id = 1;
```

#### Резервная копия базы

Просто скопируй файл `quiz.db` — это и есть вся база:
```
copy quiz-app\quiz.db quiz-app\quiz.db.backup
```

#### Полный сброс базы (начать с нуля)

Останови сервер (закрой окно start.bat), удали файл:
```
del quiz-app\quiz.db
```
При следующем запуске база создастся заново пустой.

## 5. API маршруты

### Без авторизации

| Метод | URL | Что делает |
|-------|-----|------------|
| POST | `/api/auth/register` | Регистрация. Body: `{username, email, password, role}` |
| POST | `/api/auth/login` | Вход. Body: `{login, password}`. login = username или email |
| GET  | `/api/public/tests/:code` | Найти тест по коду. Возвращает мета-данные (без вопросов) |
| POST | `/api/public/tests/:id/questions` | Получить вопросы. Body: `{password}` (если нужен) |
| POST | `/api/submissions` | Отправить ответы. Body: `{test_id, answers, student_name, password}` |
| GET  | `/api/submissions/:id` | Получить результат попытки |

### Только для учителя (нужен JWT-токен)

| Метод | URL | Что делает |
|-------|-----|------------|
| GET    | `/api/tests` | Список своих тестов |
| GET    | `/api/tests/:id` | Один тест с вопросами |
| POST   | `/api/tests` | Создать тест |
| PUT    | `/api/tests/:id` | Обновить тест |
| DELETE | `/api/tests/:id` | Удалить тест |
| GET    | `/api/tests/:id/results` | Все попытки по тесту |
| POST   | `/api/auth/onboarded` | Отметить что онбординг пройден |

### Формат ошибки

```json
{ "error": "Текст ошибки" }
```

## 6. Запуск

### Обычный запуск

```
Двойной клик на start.bat
```

Что происходит:
1. Убиваются старые процессы node и ssh
2. Стартует `node server.js` на порту 3000
3. Открывается SSH-туннель через localhost.run
4. Через ~10-40 сек появляется публичный URL `https://xxxxx.lhr.life`
5. URL открывается в браузере
6. Watchdog следит — если Node упал, перезапускает автоматически

### Только локально (без туннеля)

```powershell
cd "путь\до\quiz-app"
node server.js
```
Открыть: http://localhost:3000

### Изменить порт

В `server.js` строка 8:
```js
const PORT = process.env.PORT || 3000;  // поменяй 3000 на другой
```
В `start.ps1` строки 55 и 103 — тоже поменяй порт в `-R 80:localhost:3000`.

### Изменить JWT-секрет (для продакшена)

В `server.js` строка 9:
```js
const JWT_SECRET = 'quizmaster_secret_key_change_in_production';
// замени на длинную случайную строку
```
После смены все старые токены перестанут работать — пользователям придётся войти заново.
