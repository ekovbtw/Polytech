## Сокет
**Сокет** - механизм, с помощью которого две программы (на разных компьютерах) могут взаимодействовать по сети.
Сокету нужно:
1. IP addr компьютера
2. порт

> [!NOTE]
> С помощью порта ОС определяет кому направленны данные. 

## TCP и UDP
TCP и UDP - протоколы соединения. 
TCP работает так: 
1. установка соединения
2. передача данных
3. завершение соединения
![[Pasted image 20260913184548.png|526]]
Передача данных происходит сегментами, у каждого сегмента есть порядковый номер, чтобы клиент поставил их в правильном порядке. Получатель подтверждает получения сегмента, отправляя номер следующего. Если подтверждение не пришло за обозначенное время,  TCP отправляет повторно сегмент. 

UDP работает иначе:
1. данные идут отдельными кусками (дейтаграммами) 
2. не гарантирует получение
3. не устанавливает соединение
4. не гарантирует правильный порядок получения 
UDP работает быстрее TCP. TCP используем тогда, когда важна целостность передачи данных, а UDP - когда скорость. TCP уязвим к атакам SYN-FLOOD, а также стандартный TCP не обеспечивает шифрование данных. 

## Абстрактный алгоритм TCP 
Начинается взаимодействие клиента и сервера с того, что сервер должен быть готовым к передаче данных, а клиент к получению. Клиент создает сокет (*SOCK_STREAM*), указывает IP адрес сервера, порт соединения. Со стороны сервера тоже создается сокет, обозначить свой адрес и порт. Дальше идет SYN --> SYN/ACK --> ACK хендшейк. Открывается соединение, а в конце клиент отправляет FIN (finish), на который сервер отвечает своим FIN. 
Сервер может общаться с несколькими клиентами одновременно, если умеет работать параллельно, иначе второй клиент будет ожидать, пока первый не закончит работу. 

## Абстрактный алгоритм UDP
Начало аналогичное: клиент создает сокет (*SOCK_DGRAM*), отправка данных с помощью функции *sendto*, при этом каждый раз в саму функцию передается IP адрес и порт. Со стороны сервера создается аналогичный сокет, функцией bind привязывается адрес и порт. Дальше данные получаются через функцию recvfrom. В UDP один и тот же сокет используется для всех клиентов сразу, а сервер отвечает зная IP+порт клиента 

## Функции сокетов
Функция **socket** (создание сокета) - `int socket (int domain, int type, int protocol).` 
1. domain - семейство протоколов (какого рода адреса будут использоваться). Например для IPv4 используется флаг *AF_INET*. 
2. type - тип соединения: TCP/UDP. *SOCK_STREAM* - TCP, *SOCK_DGRAM* - UDP. 
3. protocol - обычно ставим 0, так как в type уже выбрали тип подключения. 
Функция при успешном завершении возвращает дескриптор сокета - номер, по которому можно к нему обращаться. Иначе возвращается значение -1. 

Функция **connect** (функция подключения к серверу TCP) - `int connect(int sockfd, struct sockaddr *serv_addr, socklen_t addrlen)`
1. sockfd - дескриптор сокета (который вернула функция socket)
2. serv_addr - указатель на структуру адреса сервера, используется структура sockaddr:
	1. семейство протоколов (AF_INET)
	2. порт сервера (в специальном сетевом формате)
	3. IP-адрес сервера
3. addrlen - размер структуры в байтах. 
Возвращает 0 - в случае успеха, иначе -1 (порт закрыт, сервер не отвечает).

### Сетевой порядок байт
Есть два варианта хранения числа порта: 
1. Little endian - младший байт первый (на большинстве процессоров)
2. Big endian (старший байт первый)
Проблема в том, что если у компьютеров разный порядок байт, то число прочитается неправильно на стороне получателя. Договорились, что данные передаются по сетевому порядку байт (совпадает с Big endian). Перед отправкой нужно перевести из порядка хоста в сетевой порядок, а при получении наоборот. 

Для этого есть 4 функции:
1. **htons** - host to network short, переводит 2-байтовое short число из порядка хоста в сетевой порядок. Используется для номера порта.  
2. **htonl** - host to network long, то же самое для 4-батового числа (long). Используется для IP адреса
3. ntohs - network to host short, обратное преобразование
4. ntohl - network to host long, аналогично. 

> [!Пример]
> Ты хочешь подключиться к порту 9000. Ты не можешь просто написать addr.sin_port = 9000, потому что это число хранится в памяти твоего компьютера в его собственном порядке байт, а на другой стороне сети его могут прочитать неправильно. Поэтому пишешь addr.sin_port = htons(9000) — теперь число превращено в правильный сетевой порядок, и его можно отправлять.

### Функции send, recv - отправка, прием данных
Функция отправки **send** - `int send (int sockfd, const void *buf, int len, int flags)`. 
1. sockfd - дескриптор сокета
2. buf - указатель на данные, которые хотим отправить. 
3. len - длина буфера 
4. flags - набор флагов. Рекомендуется использовать 0 или MSG_NOSIGNAL. 
Возвращает количество отправленных байт, или -1 при неудаче. 

Функция приема **recv** - `int recv (int sockfd, void *buf, int len, int flags)`. 
Аналогично, но buf - буфер, в который запишутся данные, len - максимальная длина байт за вызов. 
Возвращает количество принятых байт, или -1 при ошибке. 

send вызывают в цикле, потому что сама функция не гарантирует, что весь размер дойдет. 

### Функции bind, listen, accept
Для стороны сервера в TCP протоколе используются три функции.
**bind** (функция привязка к IP адресу) - `int bind (int sockfd, struct sockaddr *my_addr, int addrlen)`.
1. my_addr - указатель на структуру с адресом, к которому привязывается сокет. Тут заполняется структура sockaddr_in (AF_INET, порт, IP). На сервере обычно указывают, вместо конкретного IP, INADDR_ANY - слушать любые интерфейсы. 
2. addrlen - размер структуры адреса. 
Возвращает 0 при успехе, -1 при неудаче. 

Функция **listen** (перевод сокета в режим ожидания) - `int listen (int sockfd, int backlog)`. 
1. backlog - размер очереди ожидания подключения. Например, если несколько клиентов за раз подключатся к серверу, а он еще не успел обработать их подключения, то клиенты встанут в эту очередь. 

Функция **accept** (принятие подключения) - `int accept(int sockfd, struct sockaddr *addr, socklen_t, *addrlen)`  
1. addr - сюда запишется информация о клиенте: порт, IP
2. addrlen - указатель на размер структуры addr. Перед вызовом туда нужно записать максимальный размер, который можно туда положить, а после вызова там будет реальный записанный размер.
Возвращает новый дескриптор сокета, отдельный от прослушивающего. Через этот сокет ведется общение с конкретным клиентом. 

> [!Про разные сокеты]
> У тебя получается два разных сокета с разными ролями. Один — слушающий сокет, он только принимает новые подключения и никогда не используется для send/recv. Второй — сокет конкретного клиента, который тебе вернул accept, и именно через него идёт обмен данными с этим клиентом.

### Функции sendto и recvfrom
Это аналоги send и recv, но для UDP. Разница в том, что UDP сокет "не помнит" собеседника (нет connect), то адрес нужно указывать при каждой отправке, и адрес отправителя нужно получать при каждом приёме.
Функция **sendto** - `int sendto(int sockfd, const void *buf, int len, int flags, const struct sockaddr *dest_addr, int addrlen)`
1. dest_addr — указатель на структуру с адресом получателя
2. addrlen — размер этой структуры.
Возвращает количество отправленных байт, либо -1 при ошибке. В UDP вся дейтаграмма уходит целиком.

Функция **recvfrom** (функция приема) - `int recvfrom(int sockfd, void *buf, int len, int flags, struct sockaddr *from, int *fromlen)`
1. from — сюда запишется адрес того, кто прислал эту дейтаграмму. 
2. fromlen — указатель на переменную с размером структуры from.
Возвращает размер принятой дейтаграммы, либо -1 при ошибке.
