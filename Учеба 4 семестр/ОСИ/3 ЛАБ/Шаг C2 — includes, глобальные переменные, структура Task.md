#### Что меняется в объектах синхронизации

HANDLE mutex → pthread_mutex_t mutex (одна штука, логика та же)

HANDLE event и done_event → **два** pthread_cond_t. Один для уведомления потоков что появилась задача, второй для уведомления main что всё завершено. Оба работают на одном и том же mutex — это важное требование pthread_cond_wait.

#### Что меняется в структуре Task

Твоя Task сейчас: left, right, normal. Для mergesort этого не хватает.

После того как ты разбил кусок на две половины и обе отсортированы — нужно их слить. Для слияния нужно знать mid. А ещё нужно знать: это задача на сортировку куска, или уже на слияние двух готовых половин.

Значит, Task нужно дополнить:

- полем mid — граница между двумя половинами
- полем type — сортировать или сливать
- полем-указателем на общий счётчик готовности: когда обе половины готовы, счётчик дойдёт до нуля и только тогда можно добавить задачу на слияние

Счётчик готовности — это отдельная маленькая структура, которую два дочерних задания разделяют между собой. Тебе нужно где-то её хранить и не забыть освободить после слияния.
