- add_task — логика та же, только вызывается из main
- get_task — логика та же
- update_memory — логика та же

---

#### close_all — меняется полностью

Вместо CloseHandle на каждый объект синхронизации — pthread аналоги:

- pthread_mutex_destroy для mutex
- pthread_cond_destroy для каждого cond
- free для global_array и task_array
- для потоков — не CloseHandle, а pthread_join (но это в main, не в close_all)

Сигнатура close_all тоже меняется — вместо HANDLE* threads передаёшь pthread_t* threads.

#### Что добавляется новое

Тебе нужно где-то хранить текущий размер куска — он удваивается каждый раунд. Это одна глобальная переменная, начальное значение 1 или 2.

Тебе нужно где-то хранить флаг что работа полностью завершена — чтобы потоки знали что можно выходить из цикла, а не просто ждать следующего раунда.

---

#### Важно

В этом подходе потоки не завершаются после каждого раунда. Они ждут новых задач через cond_task. Main после каждого раунда формирует новые задачи и будит потоки. Только в самом конце main выставляет флаг завершения и будит все потоки через pthread_cond_broadcast.
