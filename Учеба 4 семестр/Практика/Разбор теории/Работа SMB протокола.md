**SMB (Server Message Block)** — это сетевой протокол прикладного уровня, разработанный для предоставления совместного удаленного доступа к файлам, папкам, принтерам и последовательным портам в компьютерной сети.
Связь между клиентом и сервером (запрос-ответ) разворачивается поверх TCP порт 445.
Жизненный цикл SMB протокола:
1. Согласование поддерживаемых версий SMB клиента с сервером (выбирается максимальная из возможных)
2. Аутентификация: клиент передает свои данные (например через запрос-ответ NetNTLMv2)
3. Сервер подтверждает личность пользователя
4. Подключение к ресурсу: запрос со стороны клиента конкретной папки, проверка прав со стороны сервера, выдача доступа со стороны сервера, если права клиента разрешают доступ
5. Выполнение операций: чтение, запись и так далее
6. Разрыв соединения
Передача хэша NetNTLMv2 — это базовая часть механизма аутентификации Windows (протокола NTLM), разработанная для того, чтобы один компьютер мог доказать другому, что он знает пароль пользователя, не передавая сам пароль в открытом виде по сети.
Абстрактный принцип алгоритма NetNTLMv2: 
```
[Клиент]                                        [Сервер]

|                                                          |
| ------ Type 1: NEGOTIATE (Я хочу войти) ---------------> |
| <----- Type 2: CHALLENGE (Вот тебе случайное число) ---- |
| ------ Type 3: AUTHENTICATE (Вот мой хэш-ответ) -------->|

```
- Если сервер является локальным, он берет хранящийся у него хэш вашего пароля, проделывает те же вычисления и сравнивает результат с полученным.
- Если дело происходит в корпоративной сети, сервер сам не знает вашего пароля. Он пересылает ваш ответ на Контроллер Домена. Контроллер домена проверяет правильность хэша и возвращает серверу вердикт: пустить пользователя или отказать.
