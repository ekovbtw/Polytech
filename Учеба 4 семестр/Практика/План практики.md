## 🟦 День 1 — выбор направления и сбор материалов

### 🎯 Цель:

Сформировать базу из 5–10 отчетов + выбрать финальный кейс

### Что делаешь:

- Ищешь 5–10 публичных Pentest / Bug Bounty / CVE writeups по Windows
- Фокус:
    - Local Privilege Escalation (LPE)
    - Windows Services misconfig
    - NTLM / credential abuse
    - COM / token impersonation

### 📌 Итог дня:

✔ список отчетов (ссылки)  
✔ краткая таблица: “что за уязвимость + сложность + можно ли воспроизвести”

не выполнено

## 🟦 День 2 — выбор одного кейса + анализ

### 🎯 Цель:

Выбрать **1 отчет для воспроизведения**

### Что делаешь:

- читаешь топ-3 наиболее понятных отчета
- выбираешь тот, где:
    - есть шаги
    - есть конфиг/поведение
    - можно повторить в VM

### 💡 Рекомендация:

Лучше всего выбрать:

- Windows service misconfiguration → SYSTEM  
    или
- LPE через ACL / scheduled tasks

(они 100% воспроизводимы)

### 📌 Итог дня:

✔ выбранный отчет (1 шт)  
✔ краткий разбор уязвимости (1 страница)

---

## 🟦 День 3 — проектирование лаборатории

### 🎯 Цель:

Спроектировать стенд

### Что делаешь:

- выбираешь VM:
    - Windows 10 / Windows 11 (лучше Windows 10 Pro)
- создаешь схему:
    - attacker VM (Kali Linux или Windows)
    - target VM (уязвимая Windows)
- фиксируешь:
    - IP адреса
    - NAT / Host-only сеть

### 📌 Итог дня:

✔ схема сети (можно скрин VirtualBox/VMware)  
✔ описание стенда

---

## 🟦 День 4 — развертывание Windows VM

### 🎯 Цель:

Поднять рабочую среду

### Что делаешь:

- устанавливаешь Windows VM
- ставишь:
    - Sysinternals Suite
    - Process Monitor
    - PowerShell
- создаешь пользователя:
    - user (low privilege)
    - admin (SYSTEM target)

### 📌 Итог:

✔ рабочая VM  
✔ снимок (snapshot)

---

## 🟦 День 5 — создание уязвимости (самый важный день)

### 🎯 Цель:

Симулировать уязвимость из отчета

### Варианты (выбери один):

#### 🔥 Вариант A (рекомендуется)

Unquoted Service Path → SYSTEM

#### 🔥 Вариант B

Weak folder permissions → privilege escalation

#### 🔥 Вариант C

Scheduled Task misconfiguration

---

### 📌 Итог дня:

✔ специально созданная уязвимость  
✔ подтверждение через права доступа

---

## 🟦 День 6 — эксплуатация (атака)

### 🎯 Цель:

Повторить логику реального отчета

### Что делаешь:

- используешь:
    - cmd / PowerShell
    - icacls
    - access to service binaries
- добиваешься:
    - SYSTEM / admin privileges

### 📌 фиксация:

- скриншоты команд
- вывод whoami
- event logs (если есть)

### 📌 Итог:

✔ успешная эскалация привилегий  
✔ доказательства

---

## 🟦 День 7 — анализ уязвимости

### 🎯 Цель:

Объяснить “почему это работает”

### Что пишешь:

- root cause:
    - неправильные ACL
    - unsafe service config
    - insecure execution path
- attack chain:
    - user → write access → binary replace → SYSTEM

### 📌 Итог:

✔ технический разбор причины

---

## 🟦 День 8 — исправление уязвимости (mitigation)

### 🎯 Цель:

Показать защиту

### Что делаешь:

- исправляешь:
    - ACL (icacls)
    - service path quoting
    - permissions tightening

### 📌 Пример:

- remove write access from Users
- set correct service path quoting

### 📌 Итог:

✔ исправленная конфигурация  
✔ сравнение “до / после”

---

## 🟦 День 9 — оформление отчёта

### 🎯 Цель:

Собрать финальный документ

### Структура строго по заданию:

1. Паспорт уязвимости (ссылка)
2. Тип уязвимости (CVE / class)
3. Описание проблемы
4. Архитектура стенда
5. Схема сети
6. Реализация уязвимости (конфиги / команды)
7. Эксплуатация (шаги атаки)
8. Защита (fix)

---

### 📌 Итог:

✔ готовый отчет PDF/Word  
✔ скриншоты  
✔ логика атаки полностью описана
